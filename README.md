## ✨ امکانات

### 🛒 فروش و سفارش‌گیری
- ثبت سفارش حضوری با **تولید خودکار ردیف‌های فاکتور** (بدون افزودن دستی ردیف)
- محاسبه خودکار مبالغ و خلاصه سفارش
- صدور فاکتور و کاتالوگ به‌صورت **PDF** و اشتراک‌گذاری مستقیم در
  **واتساپ، تلگرام، روبیکا و بله**

### 👥 مشتریان و محصولات
- پرونده کامل مشتری با آدرس، تلفن و سوابق خرید
- گزارش هر مشتری شامل تاریخچه سفارش‌ها و آدرس
- مدیریت محصولات و گروه‌های کالایی

### 📊 مدیریت و گزارش
- داشبورد مدیریتی با خلاصه فروش و آمار کلیدی
- گزارش فروش و عملکرد ویزیتورها

### 🔐 امنیت و سطوح دسترسی
- ورود امن با **شماره موبایل + رمز عبور** و نشست سمت سرور (توکن تصادفی + هش در دیتابیس)
- **مدیر** و کاربران عادی با سطوح دسترسی ماژولی (هر کاربر فقط بخش‌های مجاز را می‌بیند)
- **مجوزهای زمان‌دار** — ثبت‌نام و دسترسی کاربران فقط در بازه تعیین‌شده توسط مدیر
- پنل مدیریت کاربران و تمدید/لغو دسترسی

### 💾 پشتیبان‌گیری
- پشتیبان‌گیری **دستی** و **خودکار** (روزانه / هفتگی / ماهانه) — فقط توسط مدیر
- مشاهده، دانلود و حذف نسخه‌های پشتیبان
- **بازنشانی امن** برنامه (پاک‌سازی کامل داده‌ها با تأیید رمز مدیر)

### 🎨 رابط کاربری
- کاملاً **فارسی و راست‌چین (RTL)**
- تم **مینیمال لوکس طلایی**
- بهینه برای موبایل + امکان تغییر لوگوی برنامه

## 🔑 سیستم لایسنس (فعال‌سازی و شارژ مدت‌دار)

اپلیکیشن ویزیتو **لایسنس‌دار** است؛ بدون لایسنس فعال (یا بعد از انقضا) هیچ‌کدام از بخش‌ها کار نمی‌کند.
در حالت قفل، صفحه «فعال‌سازی لایسنس» نمایش داده می‌شود و **هیچ داده‌ای حذف نمی‌شود** — با شارژ مجدد، دقیقاً از همان‌جا ادامه می‌دهید.

### تولید کلید لایسنس (فروشنده — فقط روی سیستم سازنده)
```bash
npm run license:gen -- --name "نام مشتری" --mobile 09121234567 --months 12 --install-id <شناسه-نصب-مشتری>
npm run license:gen -- --name "..." --days 30  --install-id ...
npm run license:gen -- --name "..." --until 2027-01-01 --install-id ...
```
> شناسه نصب (installId) را از صفحه فعال‌سازی لایسنسِ نصب مشتری بگیرید — کلید بدون installId صادر نمی‌شود.
>
> اگر Bun در دسترس دارید، معادل `npm run license:gen:bun -- ...` هم کار می‌کند.

خروجی یک کلید امضاشده مثل `VZT2.xxxxxxxx.xxxxxxxx` است که فقط روی همان نصب کار می‌کند.

### فعال‌سازی (مشتری)
- اولین اجرای برنامه صفحه فعال‌سازی را نشان می‌دهد → شناسه نصب و کلید در همان صفحه است → کلید را از سازنده بگیرید و وارد کنید.
- بعد از انقضا هم همان صفحه ظاهر می‌شود؛ کلید جدید یا شارژ مجدد (تمدید دفتر فروش) ادامه می‌دهد.
- مدیر می‌تواند از **تنظیمات → لایسنس برنامه** وضعیت اعتبار را ببیند و همان‌جا کلید جدید را شارژ کند.

### نحوه کار فنی
- کلیدها با **Ed25519** (امضای نامتقارن، قالب VZT2) امضا می‌شوند؛ در سورس برنامه فقط «کلید عمومی» هست و کلید خصوصی فقط روی سیستم سازنده (keys/license-private.pem) است ⇒ حتی با دسترسی به کد سرور، ساخت کلید جعلی ممکن نیست.
- هر کلید به installId همان نصب قفل می‌شود و روی سرورهای دیگر کار نمی‌کند؛ انقضای مؤثر از دفتر فروش لایسنس (سرور مرجع) هم خوانده می‌شود.
- سرور در هر درخواست احراز هویت‌شده اعتبار لایسنس را چک می‌کند؛ منقضا ⇒ پاسخ `402 LICENSE_LOCKED`.
- نسخه قدیمی VZT1 (HMAC با secret داخل سورس) کاملاً حذف و باطل شده است.
- داده‌ها همیشه در دیتابیس باقی می‌مانند (قفل فقط جلوی استفاده را می‌گیرد).

## 📱 دانلود و نصب اپلیکیشن اندروید (APK)

هر بار که تغییری در مخزن پوش (push) شود، GitHub Actions به‌صورت خودکار APK جدید می‌سازد.
> ⚠ تا وقتی «آدرس سرور واقعی» هنگام اجرای دستی ورک‌فلو وارد نشده باشد، APK فقط در
> آرتیفکت‌های Actions قرار می‌گیرد و در Releases منتشر نمی‌شود (ضد انتشار APK بدون سرور).

### روش ۱ — دانلود از بخش Releases (پیشنهادی)
1. به بخش [**Releases**](https://github.com/azhinehsiroos/vizito/releases) بروید.
2. فایل `Vizito-v1.0.0.apk` را دانلود کنید.
3. فایل را باز کنید و برای نصب، اجازه «نصب از منابع ناشناس» را بدهید.

### روش ۲ — دانلود از بخش Actions
1. به تب [**Actions**](https://github.com/azhinehsiroos/vizito/actions) بروید.
2. روی آخرین اجرای «**ساخت APK ویزیتو**» کلیک کنید.
3. از بخش **Artifacts** فایل `Vizito-APK` را دانلود و نصب کنید.

## 🌐 اتصال اپلیکیشن اندروید به سرور شما

اپلیکیشن اندروید یک **پوسته امن WebView** است که نسخه وب ویزیتو را بارگذاری می‌کند؛
بنابراین برای استفاده واقعی، نسخه وب باید روی یک سرور در دسترس (VPS یا سرور داخلی
شرکت) اجرا شود. سپس آدرس سرور را به اپ بدهید:

**راه اول — هنگام اجرای دستی ورک‌فلو (ساده‌ترین راه):**
1. تب **Actions** ← «ساخت APK ویزیتو» ← **Run workflow**
2. در فیلد «آدرس سرور وب‌اپلیکیشن» آدرس HTTPS دامنه خود را وارد کنید (مثلاً `https://example.com` — فقط HTTPS)
3. دکمه Run را بزنید؛ APK جدید با آدرس سرور شما ساخته و در Releases منتشر می‌شود.

**راه دوم — ویرایش مستقیم کد:**
آدرس سرور را در این فایل جایگزین کنید و پوش کنید:

```
android/app/src/main/res/values/strings.xml
```

```xml
<string name="server_url" translatable="false">https://آدرس-سرور-شما.com</string>
```

> 💡 برای تست در شبکه داخلی می‌توانید از آدرس مثل `http://192.168.1.10:3000` استفاده کنید
> (اتصال HTTP در این اپ مجاز است). برای انتشار در **بازار یا مایکت** بهتر است سرور شما HTTPS باشد.

**قابلیت‌های اپ اندروید:** اسپلش لوکس طلایی، کشیدن برای بروزرسانی، ذخیره خودکار
فاکتورهای PDF و فایل‌های پشتیبان در پوشه Downloads، انتخاب فایل (مثل تغییر لوگو)،
دکمه بازگشت هوشمند و صفحه فارسی «اتصال برقرار نشد».

## 🖥 اجرای نسخه وب (سرور)

پیش‌نیاز Production: **Node.js 24 (الزامی)** — وابستگی html2canvas-pro@2.5.2 رسماً `node >= 24` می‌خواهد (روی هاست اشتراکی cPanel با Setup Node.js App هم اجرا می‌شود — راهنمای کامل: [docs/DEPLOY-CPANEL-FA.md](docs/DEPLOY-CPANEL-FA.md))

### تولید محلی

```bash
# ۱) نصب وابستگی‌ها (Prisma Client هم خودکار ساخته می‌شود)
npm install          # (اگر Bun در دسترس است: bun install)

# ۲) متغیرهای محیطی — از نمونه کپی کنید و مقادیر را پر کنید:
cp .env.example .env
#    DATABASE_URL، SETUP_TOKEN، BACKUP_ENCRYPTION_KEY و غیره — توضیح هر متغیر داخل .env.example هست

# ۳) جداول دیتابیس (نصب تازه — هر دو مهاجرت رسمی اعمال می‌شوند)
npm run db:deploy

# ۴) اجرای توسعه
npm run dev
```

### Production (هر سرور لینوکسی با Node.js)

```bash
npm install
npm run build    # prisma generate + next build + بسته‌بندی Standalone
npm start        # server.cjs: بررسی‌ها + prisma migrate deploy (با قفل) + اجرای server.js با node
```

- `npm start` بدون Bun و بدون tee است؛ اگر مهاجرت شکست بخورد سرور بالا نمی‌آید و خطا کامل نمایش داده می‌شود.
- فایل راه‌انداز `server.cjs` مسیر دیتابیس/داده‌ها را قبل از شروع بررسی و پوشه‌ها را می‌سازد.

اپلیکیشن روی پورت ۳۰۰۰ بالا می‌آید. **روی نصب تازه، اولین ثبت‌نام فقط با «کد راه‌اندازی
اولیه» (SETUP_TOKEN) ممکن است** و آن کاربر مدیر برنامه می‌شود؛ ثبت‌نام‌های بعدی فقط با
کد دعوت مدیر. درخواست‌های هم‌زمان برای اولین ثبت‌نام هم تنها یک مدیر می‌سازند (قفل اتمیک در سطح دیتابیس). شماره‌های سازنده (OWNER_MOBILES) فقط با «کلید راه‌اندازی سازنده»
(OWNER_SETUP_KEY) ثبت می‌شوند و بدون نیاز به کد دعوت، دسترسی همیشگی دارند.

## 🔐 نکات امنیتی

- فایل `.env`، پوشه `keys/` (کلید خصوصی امضای لایسنس) و `android/keystore/`
  (امضای APK) **هرگز** در مخزن قرار نمی‌گیرند.
- لایسنس فقط نسخه VZT2 با امضای نامتقارن Ed25519 است (نسخه قدیمی VZT1 کاملاً باطل شده)؛
  هر کلید به installId یک نصب قفل می‌شود و صدور کلید بدون installId ممکن نیست.
- امضای APK در GitHub Actions از Secrets (KEYSTORE_B64 / KEYSTORE_PASSWORD / KEY_ALIAS /
  KEY_PASSWORD) بازسازی می‌شود — keystore را خارج از سیستم هم پشتیبان نگه دارید!
- فایل‌های پشتیبان با AES-256-GCM و کلید env: BACKUP_ENCRYPTION_KEY رمزنگاری می‌شوند و
  شامل نشست‌های فعال نیستند؛ رمزگشایی:
  `BACKUP_ENCRYPTION_KEY=... npm run backup:decrypt -- <فایل پشتیبان> -o خروجی.json`
- دیتابیس و فایل‌های پشتیبان خارج از مسیر عمومی نگهداری می‌شوند و مسیر دانلودها
  در برابر Path Traversal محافظت می‌شود.
- تمام مسیرهای مدیریتی در سرور بررسی دسترسی می‌شوند (نه فقط در رابط کاربری).
- کوکی نشست HttpOnly + SameSite=Strict است و توکن در localStorage ذخیره نمی‌شود؛
  ضد CSRF مبدأ بررسی می‌شود و محدودسازی نرخ ورود/ثبت‌نام در دیتابیس ماندگار است.
- خروجی Production فقط Standalone است؛ بررسی کنید فایل‌های `.env`، دیتابیس و کلیدها
  داخل ZIP/آپلود استقرار نباشند (راهنمای استقرار، فهرست دقیق آپلود را می‌دهد).
