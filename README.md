### 💾 پشتیبان‌گیری

- **بازنشانی امن** برنامه (پاک‌سازی کامل داده‌ها با تأیید رمز مدیر)

## 💰 مدل درآمدی و چرخه عمر نصب (v1.1.x)

1. **نصب تازه** → اولین ثبت‌نام فقط با «کد راه‌اندازی اولیه» (SETUP_TOKEN) و همان حساب **مدیر کل** می‌شود.
2. **ترِیال ۲۴ ساعته** خودکار برای نصب تازه + هر کاربر عمومیِ ثبت‌نامی یک ترِیال شخصی ۲۴ ساعته می‌گیرد (یک‌بار، سمت سرور، با ثبت‌نام مجدد ریست نمی‌شود).
3. پس از ترِیال، بخش‌های اصلی با `402` قفل می‌شوند؛ **ورود و مشاهده وضعیت آزاد است و هیچ داده‌ای حذف نمی‌شود**.
4. با خرید لایسنس همه‌چیز دقیقاً از همان‌جا ادامه پیدا می‌کند.
5. **پس از انقضای لایسنس، مهلت تمدید ۳۰ روزه**: ورود آزاد، قفل عملیات، شمارش معکوس در صفحه قفل. اگر تمدید نشود، «حذف کنترل‌شده» اجرا می‌شود (ابتدا پشتیبان رمزنگاری‌شده — اگر پشتیبان شکست بخورد حذف لغو می‌شود؛ سپس حذف داده‌های تجاری و حساب‌های مدیرِ غیرِمالک؛ حساب مالک و پرسنل حفظ می‌شود). مالک می‌تواند حذف را از دفتر فروش **متوقف/ادامه/دستی** کند.
6. حساب‌های «سازنده برنامه» (OWNER_MOBILES) و پرسنل، از قفل ترِیال عمومی معاف‌اند؛ انقضای خود لایسنس همه را قفل می‌کند (به‌جز مالک).

## 🔑 سیستم لایسنس (فعال‌سازی و شارژ)

- پلن‌ها: **۱ / ۳ / ۶ / ۱۲ ماهه** + **دائمی** (یک‌بار خرید، بدون تاریخ انقضا — خارج از چرخه مهلت/حذف).
- کلیدها با **Ed25519** (قالب VZT2) امضا می‌شوند؛ در سورس فقط «کلید عمومی» هست و کلید خصوصی فقط روی سیستم سازنده (`keys/license-private.pem`) است ⇒ ساخت کلید جعلی ممکن نیست.
- هر کلید به **installId** همان نصب قفل می‌شود؛ صدور بدون installId ممنوع است (ضد اشتراک‌گذاری).
- **تمدید زودهنگام، زمان باقیمانده را دقیقاً حفظ می‌کند** (شارژ روی دفتر فروش همان نصب).
- سرور در هر درخواستِ احراز هویت‌شده اعتبار را چک می‌کند؛ منقضا ⇒ پاسخ `402` با جزئیات مهلت تمدید.

### تولید کلید لایسنس (فروشنده — فقط روی سیستم سازنده)
```bash
npm run license:gen -- --name "نام مشتری" --mobile 09121234567 --months 12 --install-id <شناسه-نصب-مشتری>
npm run license:gen -- --name "..." --days 30      --install-id ...
npm run license:gen -- --name "..." --until 2027-01-01 --install-id ...
npm run license:gen -- --name "..." --permanent    --install-id ...   # لایسنس دائمی (e=0)
```
> شناسه نصب (installId) را از صفحه فعال‌سازی لایسنسِ نصب مشتری بگیرید. اگر Bun دارید معادل `npm run license:gen:bun -- ...` هم کار می‌کند. خروجی کلیدی مثل `VZT2.xxxxxxxx.xxxxxxxx` است.

### فعال‌سازی (مشتری)
- اولین اجرای برنامه صفحه فعال‌سازی را نشان می‌دهد → شناسه نصب و کلید در همان صفحه است → کلید را از سازنده بگیرید و وارد کنید.
- بعد از انقضا همان صفحه با **شمارش معکوس مهلت تمدید** ظاهر می‌شود؛ کلید جدید یا شارژ از دفتر فروش ادامه می‌دهد.
- مدیر از **تنظیمات → لایسنس برنامه** وضعیت اعتبار را می‌بیند؛ مالک از **دفتر فروش لایسنس** صدور/شارژ/توقف حذف را انجام می‌دهد.

## 🚀 راه‌اندازی اولیه امن (گام‌به‌گام)

> کلیدها فقط روی سرور (env) زندگی می‌کنند — هرگز در کد، لاگ، README یا رابط کاربری مقدارشان دیده نمی‌شود. فیلدهای کلید در UI فقط بعد از پاسخ ۴۰۳ سرور ظاهر می‌شوند و مقدارشان به‌صورت password input ارسال می‌شود.

**گام ۱ — تولید مقادیر تصادفی (روی سیستم خودتان، نه سرور مشتری):**
```bash
openssl rand -hex 24      # → SETUP_TOKEN
openssl rand -hex 24      # → OWNER_SETUP_KEY  (فقط نصب سازنده)
openssl rand -base64 48   # → BACKUP_ENCRYPTION_KEY
```

**گام ۲ — تنظیم env روی سرور** (cPanel → Setup Node.js App → Environment variables، یا فایل `.env` کنار پروژه):
- `DATABASE_URL` — مسیر مطلق SQLite **بیرون از public_html** (الزامی)
- `VIZITO_DATA_DIR` — پوشه داده‌های ماندگار بیرون از public_html (توصیه‌شده)
- `SETUP_TOKEN` — کد راه‌اندازی اولیه (**قبل از اولین اجرا** بگذارید؛ بدون آن نصب تازه قابل راه‌اندازی نیست)
- `BACKUP_ENCRYPTION_KEY` — برای رمزنگاری پشتیبان‌ها (بدون آن پشتیبان خطا می‌دهد)
- فقط روی **نصب سازنده**: `OWNER_MOBILES` + `OWNER_SETUP_KEY` (نصب مشتری هر دو را خالی بگذارد)
- روی هاست‌های پشت Passenger: `TRUSTED_PROXY_HOPS=1`

**گام ۳ — ساخت و اجرا:**
```bash
npm install
npm run build     # prisma generate + next build + بسته‌بندی Standalone
npm start         # server.cjs: بررسی‌ها + مهاجرت‌ها (با قفل) + اجرای سرور
```

**گام ۴ — اولین ثبت‌نام از رابط کاربری:**
1. برنامه را باز کنید؛ اگر هیچ حسابی نباشد، خودکار تب «ثبت‌نام» + فیلد «کد راه‌اندازی اولیه» باز می‌شود.
2. شماره موبایل، نام و SETUP_TOKEN را وارد کنید → این حساب **مدیر کل** می‌شود.
3. از این لحظه مسیر «اولین مدیر» **برای همیشه** بسته می‌شود (قفل اتمیک در دیتابیس — حتی با درخواست‌های هم‌زمان فقط یک مدیر ساخته می‌شود) و SETUP_TOKEN بی‌اثر است؛ می‌توانید از env حذفش کنید.
4. ثبت‌نام‌های بعدی فقط با **کد دعوت مدیر** (تنظیمات → کد دعوت) انجام می‌شود.

**نقش سازنده (اختیاری):** اگر `OWNER_MOBILES` تنظیم شده باشد، ثبت‌نام با آن شماره‌ها فقط با `OWNER_SETUP_KEY` درست ممکن است؛ ثبت‌نام مجدد مالک با کلید درست فقط **همان حساب موجود** را ارتقا می‌دهد (بازیابی) و **هرگز حساب مالک دوم نمی‌سازد**. کلید نادرست/نبودِ کلید = رد شدن (fail-closed).

## 📱 اپلیکیشن اندروید (APK) و آدرس سرور

اپ اندروید یک **پوسته امن WebView** است که نسخه وب را بارگذاری می‌کند — یعنی وب باید روی یک سرور در دسترس اجرا شده باشد و آدرس سرور داخل APK ثبت شود:

- **GitHub Actions** هر بار push به main یا اجرای دستی «Run workflow»، APK می‌سازد. در اجرای دستی، فیلد «آدرس سرور وب‌اپلیکیشن» را با HTTPS دامنه خودتان پر کنید.
- یا آدرس سرور را در `android/app/src/main/res/values/strings.xml` (`server_url`) جایگزین کنید و بیلد بگیرید.
- برای تست داخلی HTTP مثل `http://192.168.1.10:3000` مجاز است؛ برای انتشار در بازار/مایکت HTTPS توصیه می‌شود.
- قابلیت‌های اپ: اسپلش طلایی، کشیدن برای بروزرسانی، ذخیره PDF/پشتیبان در پوشه Downloads، انتخاب فایل، دکمه بازگشت هوشمند و صفحه فارسی «اتصال برقرار نشد».

## 🖥 اجرای نسخه وب

پیش‌نیاز: **Node.js 24 (الزامی)** — روی cPanel با Setup Node.js App هم اجرا می‌شود (راهنمای کامل: [docs/DEPLOY-CPANEL-FA.md](docs/DEPLOY-CPANEL-FA.md))

### توسعه محلی
```bash
npm install                # (یا: bun install) — Prisma Client خودکار ساخته می‌شود
cp .env.example .env       # متغیرها را پر کنید — توضیح هر متغیر داخل .env.example است
npm run db:deploy          # اعمال هر ۵ مهاجرت رسمی (روی نصب تازه)
npm run dev
```

### Production (هر سرور لینوکسی با Node.js)
```bash
npm install
npm run build    # prisma generate + next build + بسته‌بندی Standalone
npm start        # server.cjs: بررسی‌ها + prisma migrate deploy (با قفل) + اجرای server.js
```
- `npm start` مهاجرت‌ها را امن اعمال می‌کند: مهاجرت ناقص/ناسازگار ⇒ توقف بدون تغییر (پایه ساختاری SQLite + اعتبارسنجی باینری‌های لینوکسی در بسته استقرار).
- بسته قابل استقرار: `npm run deploy:package` → ZIP با اسکن محرمانگی و اعتبارسنجی ELF/GLIBC.

## 🔐 نکات امنیتی

- فایل `.env`، پوشه `keys/` (کلید خصوصی لایسنس) و `android/keystore/` **هرگز** در مخزن قرار نمی‌گیرند.
- **هیچ کلید/رمز/توکنی در لاگ‌ها ثبت نمی‌شود** — نه مقدار SETUP_TOKEN/OWNER_SETUP_KEY و نه وضعیت تطبیق‌شان.
- ثبت‌نام اولین مدیر: قفل اتمیک دیتابیس + محدودیت نرخ (۵/ساعت per-IP، ۳/۱۰دقیقه per-شماره) + مقایسه امن timing-safe.
- کوکی نشست HttpOnly + SameSite=Strict؛ توکن در JS/localStorage نیست؛ ضد CSRF دو لایه‌ای (application/json + Origin/Referer).
- همه مجوزها در سرور بررسی می‌شوند (`requireAuth`)؛ UI فقط نمایشی است — دور زدن APK/ساعت/API ممکن نیست.
- داده هر کاربر ایزوله است (بدون مجوز `all_customers` فقط داده خودش را می‌بیند) و قیمت خرید فقط برای نقش مجاز نمایان است.
- امضای APK در GitHub Actions از Secrets بازسازی می‌شود — keystore را خارج از سیستم هم پشتیبان نگه دارید!
- فایل‌های پشتیبان رمزنگاری‌شده با `BACKUP_ENCRYPTION_KEY`؛ رمزگشایی:
  `BACKUP_ENCRYPTION_KEY=... npm run backup:decrypt -- <فایل پشتیبان> -o خروجی.json`
- خروجی Production فقط Standalone است؛ مطمئن شوید `.env`، دیتابیس و کلیدها داخل ZIP استقرار نیستند (اسکن خودکار بسته‌بند جلویش را می‌گیرد).
