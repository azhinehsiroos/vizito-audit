- مدیریت محصولات و گروه‌های کالایی

### 📊 مدیریت و گزارش

### 📨 صندوق پیام و اطلاع‌رسانی

  همه کاربران / مدیران / پرسنل / خریداران لایسنس / اعتبار نزدیک انقضا / منقضی / در مهلت تمدید
- تاریخچه ارسال‌ها با وضعیت خوانده‌شدن هر گیرنده و حذف نرم

### 💾 پشتیبان‌گیری
- پشتیبان‌گیری **دستی** و **خودکار** (روزانه / هفتگی / ماهانه) — فقط توسط مدیر
- فایل‌های پشتیبان با **AES-256-GCM** رمزنگاری می‌شوند
- **بازنشانی امن** برنامه (پاک‌سازی کامل داده‌ها — فقط سازندهٔ برنامه، با تأیید رمز؛ حساب سازنده حفظ می‌شود)

### 🎨 رابط کاربری
- کاملاً **فارسی و راست‌چین (RTL)** — تقویم هجری شمسی
- تم **مینیمال لوکس طلایی** + دارک مود
- بهینه برای موبایل (390px) + امکان تغییر لوگوی برنامه

### ☁️ نسخه SaaS چندمجموعه‌ای (v2.0.0)
- **مجموعه‌های مستقل** — هر مشتری سازمان خودش را دارد: کاربران، مشتریان، کالاها و سفارش‌ها کاملاً از بقیه مجموعه‌ها ایزوله‌اند (۴۰۴ بدون افشا)
- **پنل «مدیریت کل» سازنده** — فهرست مجموعه‌ها، لایسنس هر مجموعه، فروش لایسنس، توقف/ادامه، پشتیبان‌گیری FULL و حسابرسی کامل (AdminAccessLog)
- **«مجموعه من»** — حساب سازنده علاوه بر پنل مدیریتی، یک مجموعه اختصاصی با لایسنس دائمی دارد و مثل یک مدیر مجموعه معمولی روی آن کار می‌کند
- **همگام‌سازی چنددستگاهی** — داده‌ها و سفارش‌های یک مجموعه بین دستگاه‌هایش همگام می‌شوند؛ ضدتکرار با clientRef یکتا سمت سرور (idempotent)
- **حالت آفلاین واقعی** — ثبت سفارش بدون اینترنت با صف محلی رمزنگاری‌شده (AES-256-GCM)؛ خروج از حساب یا بستن برنامه هرگز سفارشِ همگام‌نشده را حذف نمی‌کند و حذف از صف فقط پس از تأیید سرور انجام می‌شود
- **پشتیبانی داخلی** — تیکت و گفتگوی مستقیم هر مجموعه با تیم پشتیبانی سازنده (حتی در حالت قفل تجاری کار می‌کند)
- **پشتیبان‌گیری تفکیک‌شده** — بکاپ هر مجموعه فقط داده همان مجموعه را دارد و بازگردانی فقط به همان مجموعه ممکن است؛ بکاپ FULL کل سرور فقط سازنده با opt-in صریح

## 💰 مدل درآمدی و چرخه عمر (v2.0.0 — SaaS چندمجموعه‌ای)

1. هر **مجموعه (سازمان)** مستقل ثبت‌نام می‌کند؛ **اولین ثبت‌نام هر نصب** فقط با «کد راه‌اندازی اولیه» (SETUP_TOKEN) ممکن است و همان حساب **مدیر مجموعه** می‌شود. ثبت‌نام‌های بعدی فقط با **کد دعوت** — منبع کد دعوت فقط «سازنده برنامه» است.
2. هر مجموعهٔ تازه یک **ترِیال ۲۴ ساعتهٔ سمت سرور** می‌گیرد (یک‌بار؛ با ثبت‌نام مجدد ریست نمی‌شود).
3. پس از ترِیال، عملیات‌های اصلی با `402` قفل می‌شوند؛ **ورود و مشاهده وضعیت آزاد است و هیچ داده‌ای حذف نمی‌شود**.
4. با خرید لایسنس (صدور از پنل فروش سازنده) همه‌چیز دقیقاً از همان‌جا ادامه پیدا می‌کند.
5. **پس از انقضای لایسنس، مهلت تمدید ۳۰ روزه با شمارش معکوس**: در این فاز و پس از آن عملیات مدیریتی قفل می‌ماند اما **داده‌ها برای همیشه محفوظ‌اند** — هیچ مسیر حذف خودکار وجود ندارد؛ تمدید در هر لحظه همه‌چیز را از همان‌جا برمی‌گرداند. سفارش‌های آفلاینِ از قبل ثبت‌شده حتی پس از انقضا قابل همگام‌سازی‌اند.
6. **تعلیق امنیتی (SUSPENDED)** فقط توسط پشتیبانی سازنده اعمال/رفع می‌شود، همه‌چیز (از جمله همگام‌سازی) را قفل می‌کند و خودفعال‌سازی با کلید جدید ممکن نیست.
7. حساب‌های «سازنده برنامه» (OWNER_MOBILES) از قفل ترِیال معاف‌اند و فقط با `OWNER_SETUP_KEY` ساخته/بازیابی می‌شوند (fail-closed — کلید نادرست = رد شدن).

## 🔑 سیستم لایسنس (فعال‌سازی و تمدید)

- هر مجموعه **لایسنس مستقل** خودش را دارد. پلن‌ها: **۳۰ / ۹۰ / ۱۸۰ / ۳۶۵ روزه** + **دائمی** (بدون تاریخ انقضا).
- کلیدهای مجموعه با قالب **VZT3** و امضای **Ed25519** صادر می‌شوند: `VZT3.<payload>.<signature>` — payload به **شناسه مجموعه (orgId)** گره خورده است؛ یک کلید فقط همان مجموعه را فعال می‌کند و هش کلید در دیتابیس ثبت می‌شود تا استفاده مجدد از همان کلید برای مجموعهٔ دیگر ممکن نباشد.
- صدور/تمدید/تعلیق فقط از **پنل فروش سازنده** انجام می‌شود (با حسابرسی کامل)؛ در سورس فقط «کلید عمومی» هست و کلید خصوصی فقط روی سرور سازنده (env یا `keys/license-private.pem`) است ⇒ ساخت کلید جعلی ممکن نیست.
- **تمدید زودهنگام، زمان باقیمانده را دقیقاً حفظ می‌کند** (روی سابقه لایسنس همان مجموعه).
- سرور در هر درخواستِ احراز هویت‌شده اعتبار را چک می‌کند؛ منقضا ⇒ پاسخ `402` با جزئیات مهلت تمدید.
- قالب قدیمی **VZT2** (اتصال به installId نصب) برای سازگاری نصب‌های قدیمی همچنان پذیرفته می‌شود؛ صدورش فقط با ابزار خط فرمان سازنده:

### تولید کلید VZT2 (سازنده — فقط نصب‌های قدیمی)
```bash
npm run license:gen -- --name "نام مشتری" --mobile 09121234567 --months 12 --install-id <شناسه-نصب-مشتری>
npm run license:gen -- --name "..." --days 30      --install-id ...
npm run license:gen -- --name "..." --until 2027-01-01 --install-id ...
npm run license:gen -- --name "..." --permanent    --install-id ...   # لایسنس دائمی (e=0)
```
> شناسه نصب (installId) را از صفحه فعال‌سازی لایسنسِ نصب مشتری بگیرید. اگر Bun دارید معادل `npm run license:gen:bun -- ...` هم کار می‌کند. کلید مجموعه‌های v2.0 را از **پنل فروش سازنده** بگیرید (انتخاب مجموعه + پلن → تولید کلید VZT3 → ارسال به مشتری).

### فعال‌سازی (مشتری)
- مدیر مجموعه از **تنظیمات → لایسنس برنامه** کلید را وارد می‌کند؛ وضعیت اعتبار و شمارش معکوس همان‌جا دیده می‌شود.
- بعد از انقضا همان صفحه با **شمارش معکوس مهلت تمدید** ظاهر می‌شود؛ کلید جدید یا تمدید از پنل فروش سازنده ادامه می‌دهد.
- سازنده از **پنل «مدیریت کل» → فروش لایسنس** صدور/تمدید/تعلیق/رفع تعلیق هر مجموعه را انجام می‌دهد (همهٔ اقدامات حسابرسی می‌شوند).

## 🚀 راه‌اندازی اولیه امن (گام‌به‌گام)

> کلیدها فقط روی سرور (env) زندگی می‌کنند — هرگز در کد، لاگ، README یا رابط کاربری مقدارشان دیده نمی‌شود. فیلدهای کلید در UI فقط بعد از پاسخ ۴۰۳ سرور ظاهر می‌شوند و مقدارشان به‌صورت password input ارسال می‌شود.

**گام ۱ — تولید مقادیر تصادفی (روی سیستم خودتان، نه سرور مشتری):**
```bash
openssl rand -hex 24      # → SETUP_TOKEN
openssl rand -hex 24      # → OWNER_SETUP_KEY  (فقط نصب سازنده)
openssl rand -base64 48   # → BACKUP_ENCRYPTION_KEY
```

**گام ۲ — تنظیم env روی سرور** (cPanel → Setup Node.js App → Environment variables، یا فایل `.env` کنار پروژه):
- `DATABASE_URL` — مسیر مطلق SQLite **بیرون از public_html** (الزامی)
- `VIZITO_DATA_DIR` — پوشه داده‌های ماندگار بیرون از public_html (توصیه‌شده)
- `SETUP_TOKEN` — کد راه‌اندازی اولیه (**قبل از اولین اجرا** بگذارید؛ بدون آن نصب تازه قابل راه‌اندازی نیست)
- `BACKUP_ENCRYPTION_KEY` — برای رمزنگاری پشتیبان‌ها (بدون آن پشتیبان خطا می‌دهد)
- فقط روی **نصب سازنده**: `OWNER_MOBILES` + `OWNER_SETUP_KEY` (نصب مشتری هر دو را خالی بگذارد)
- روی هاست‌های پشت Passenger: `TRUSTED_PROXY_HOPS=1`

**گام ۳ — ساخت و اجرا:**
```bash
npm install
npm run build     # prisma generate + next build + بسته‌بندی Standalone
npm start         # server.cjs: بررسی‌ها + مهاجرت‌ها (با قفل) + اجرای سرور
```

**گام ۴ — اولین ثبت‌نام از رابط کاربری:**
1. برنامه را باز کنید؛ اگر هیچ حسابی نباشد، خودکار تب «ثبت‌نام» + فیلد «کد راه‌اندازی اولیه» باز می‌شود.
2. شماره موبایل، نام و SETUP_TOKEN را وارد کنید → **اولین مجموعه** ساخته می‌شود و این حساب **مدیر مجموعه** با ترِیال ۲۴ ساعته است.
3. از این لحظه مسیر «اولین مجموعه» **برای همیشه** بسته می‌شود (قفل اتمیک در دیتابیس — حتی با درخواست‌های هم‌زمان فقط یک مجموعه ساخته می‌شود) و SETUP_TOKEN بی‌اثر است؛ می‌توانید از env حذفش کنید.
4. ثبت‌نام‌های بعدی (هر مجموعهٔ تازه) فقط با **کد دعوت** انجام می‌شود — منبع کد دعوت فقط «سازنده برنامه» است (مدیر مجموعه نمی‌سازد/نمی‌بیند/نمی‌چرخاند).

**نقش سازنده (اختیاری):** اگر `OWNER_MOBILES` تنظیم شده باشد، ثبت‌نام با آن شماره‌ها فقط با `OWNER_SETUP_KEY` درست ممکن است؛ ثبت‌نام مجدد مالک با کلید درست فقط **همان حساب موجود** را ارتقا می‌دهد (بازیابی) و **هرگز حساب مالک دوم نمی‌سازد**. کلید نادرست/نبودِ کلید = رد شدن (fail-closed).

## 📱 اپلیکیشن اندروید (APK) و آدرس سرور

اپ اندروید یک **پوسته امن WebView** است که نسخه وب را بارگذاری می‌کند — یعنی وب باید روی یک سرور در دسترس اجرا شده باشد و آدرس سرور داخل APK ثبت شود:

- **GitHub Actions** هر بار push به main یا اجرای دستی «Run workflow»، APK می‌سازد. در اجرای دستی، فیلد «آدرس سرور وب‌اپلیکیشن» را با HTTPS دامنه خودتان پر کنید.
- یا آدرس سرور را در `android/app/src/main/res/values/strings.xml` (`server_url`) جایگزین کنید و بیلد بگیرید.
- برای تست داخلی HTTP مثل `http://192.168.1.10:3000` مجاز است؛ برای انتشار در بازار/مایکت HTTPS توصیه می‌شود.
- قابلیت‌های اپ: اسپلش طلایی، کشیدن برای بروزرسانی، ذخیره PDF/پشتیبان در پوشه Downloads، انتخاب فایل، دکمه بازگشت هوشمند و صفحه فارسی «اتصال برقرار نشد».

## 🖥 اجرای نسخه وب

پیش‌نیاز: **Node.js 24 (الزامی)** — روی cPanel با Setup Node.js App هم اجرا می‌شود (راهنمای کامل: [docs/DEPLOY-CPANEL-FA.md](docs/DEPLOY-CPANEL-FA.md))

### توسعه محلی
```bash
npm install                # (یا: bun install) — Prisma Client خودکار ساخته می‌شود
cp .env.example .env       # متغیرها را پر کنید — توضیح هر متغیر داخل .env.example است
npm run db:deploy          # اعمال هر ۶ مهاجرت رسمی (روی نصب تازه)
npm run dev
```

### Production (هر سرور لینوکسی با Node.js)
```bash
npm install
npm run build    # prisma generate + next build + بسته‌بندی Standalone
npm start        # server.cjs: بررسی‌ها + prisma migrate deploy (با قفل) + اجرای server.js
```
- `npm start` مهاجرت‌ها را امن اعمال می‌کند: مهاجرت ناقص/ناسازگار ⇒ توقف بدون تغییر (پایه ساختاری SQLite + اعتبارسنجی باینری‌های لینوکسی در بسته استقرار).
- بسته قابل استقرار: `npm run deploy:package` → ZIP با اسکن محرمانگی و اعتبارسنجی ELF/GLIBC.

## 🔐 نکات امنیتی

- فایل `.env`، پوشه `keys/` (کلید خصوصی لایسنس) و `android/keystore/` **هرگز** در مخزن قرار نمی‌گیرند.
- **هیچ کلید/رمز/توکنی در لاگ‌ها ثبت نمی‌شود** — نه مقدار SETUP_TOKEN/OWNER_SETUP_KEY و نه وضعیت تطبیق‌شان.
- ثبت‌نام اولین مدیر: قفل اتمیک دیتابیس + محدودیت نرخ (۵/ساعت per-IP، ۳/۱۰دقیقه per-شماره) + مقایسه امن timing-safe.
- کوکی نشست HttpOnly + SameSite=Strict؛ توکن در JS/localStorage نیست؛ ضد CSRF دو لایه‌ای (application/json + Origin/Referer).
- همه مجوزها در سرور بررسی می‌شوند (`requireAuth`)؛ UI فقط نمایشی است — دور زدن APK/ساعت/API ممکن نیست.
- داده هر کاربر ایزوله است (بدون مجوز `all_customers` فقط داده خودش را می‌بیند) و قیمت خرید فقط برای نقش مجاز نمایان است.
- کلید خصوصی لایسنس (VZT3) فقط در env/سیستم سازنده است و **هرگز در باندل کلاینت یا مخزن عمومی** قرار نمی‌گیرد؛ صدور کلید فقط از پنل فروش سازنده انجام می‌شود.
- داده‌های محلی دستگاه (اسنپ‌شات/صف سفارش‌های آفلاین) با **AES-256-GCM (WebCrypto)** رمزنگاری می‌شوند؛ حد واقعی این محافظت (کلید در همان پروفایل مرورگر/WebView است) به‌صورت شفاف در سربرگ `src/lib/idb.ts` مستند شده — ادعای امنیت کاذب وجود ندارد.
- امضای APK در GitHub Actions از Secrets بازسازی می‌شود — keystore را خارج از سیستم هم پشتیبان نگه دارید!
- فایل‌های پشتیبان رمزنگاری‌شده با `BACKUP_ENCRYPTION_KEY`؛ رمزگشایی:
  `BACKUP_ENCRYPTION_KEY=... npm run backup:decrypt -- <فایل پشتیبان> -o خروجی.json`
- خروجی Production فقط Standalone است؛ مطمئن شوید `.env`، دیتابیس و کلیدها داخل ZIP استقرار نیستند (اسکن خودکار بسته‌بند جلویش را می‌گیرد).
